# SC-01 — Speed-comparison feasibility

**Cloudflare Browser Rendering pricing (effective August 2025):** $0.09 per browser-hour, with concurrent browsers beyond the plan allowance billed at $2.00/browser/month. The Workers Free Plan includes 10 minutes of browser time per day (3 concurrent browsers); the Workers Paid Plan includes 10 hours per month (10 concurrent browsers, measured as the monthly average of daily peaks). The target workload — one weekly run against two URLs at ~30 s each — totals roughly 4 minutes per month. That is well within the Free Plan's ~300 min/month allowance, leaving >98 % headroom. Even if the run were promoted to daily, the total would be ~60 min/month, still inside the free tier. Monthly cost in any realistic scenario: $0.

**livefpl.net scraping posture:** Direct `curl -I` attempts were blocked at the sandbox network boundary before reaching the target server (`x-deny-reason: host_not_allowed`), so live response headers could not be confirmed. From public sources, livefpl.net is a JavaScript-heavy SPA (React, 196+ detected technologies, native app counterparts on iOS/Android), meaning a plain HTTP fetch returns an empty shell — a real browser is required to render any comparable DOM. No confirmed CSP `frame-ancestors` restriction or hard User-Agent block was found in public documentation or community reports. The site likely sits behind Cloudflare's standard edge protection, which is compatible with headless Chromium on Workers (Cloudflare's own product). **Production path: Browser Rendering.** If Cloudflare's bot-management tier on livefpl.net proves to block the headless session in practice, fall back to SC-08 hand-curated screenshots.
